# Galaxy XR Framebuffer10 0.5.0 (experimental)

Author: **4uva4ek**. Continuous 10-bit SDR output with correct colours on Galaxy XR
firmware I610UEU2AZF3. The compositor's final rounding step becomes four times finer
(1024 instead of 256 levels per channel): less banding in dark scenes, gradients,
fades, vignettes, camera passthrough and 10-bit video. It is not HDR: brightness,
gamut and the HDR-to-SDR tone curve are unchanged.

Status: validated on the owner's headset (2026-10-19) — cameras, home screen and
Steam Link look like stock 8-bit output, including the quad-view inset. 0.5.0 ships
no vendor code; the colour library is generated on the headset.

## Requirements

- Galaxy XR (SM-I610) on I610UEU2AZF3. Any other firmware fails preflight and the
  module stays disabled.
- KernelSU GXR 1.0.6 or later: coordinated restart hooks and the generic GXR
  lifecycle installer.

## Colour fix

The 10-bit framebuffer (`A2B10G10R10_UNORM`) does not sRGB-encode on store, unlike
the stock `R8G8B8A8_SRGB` target, so the compositor would write linear light. Native
code asks each shader to encode with the output flag `0x400000000`; most vendor
shaders honour it. Seven do not:

| Shader | Defect |
| --- | --- |
| camera passthrough, constants / uniforms | encode flag missing / never read |
| projection + camera, two projections + camera | camera flag unused, projections encoded before the mix |
| AMRP reprojection, constants / uniforms | encode flag missing / never read (frames reprojected under load) |
| two projections (quad-view inset, e.g. Steam Link's sharp centre) | Hi/Lo encoded separately, then blended |

Each gets the exact piecewise sRGB encode under the flag native code already sets;
merged shaders encode once after their in-shader composition, matching the stock
8-bit math. With the flag off the code is identical to the original. Native code,
ELF layout and registered shader sizes are unchanged. An emulation audit of all 21
native `populate*Frag` functions found no other shader that receives the flag
without encoding.

## No vendor code in the package

Before the first activation `bin/gxr-fb10-gate --build-payload` reads the headset's
own `/system/lib64/libvulkan_compositor.so`, checks its SHA-256, applies the
project edit script (`native/payload_patch.inc`: copy/skip counts over stock
instructions plus inserted project instructions) and installs the result in the
module folder only if its SHA-256 matches the pinned value. It runs from the
KernelSU prepare hook and is a no-op once a verified library exists.

The edit script is generated by
[`payload-recipe/make_payload.py`](payload-recipe/make_payload.py), which also
builds the same library on a PC from a pulled stock copy (SPIRV-Tools required).

## Lifecycle

Packages install disabled. Checking the module takes effect at the next KernelSU
soft reboot:

- ON + soft reboot: while Android is stopped the module binds the generated library
  read-only over the compositor library path and sets the 10-bit selector; KernelSU
  starts Android once; after verification the bind and selector are removed.
- Unchecking restores stock 8-bit output (the guardian restores the original library
  and service flags; the Android interface restarts).
- `sh /data/adb/modules/gxr_framebuffer10/action.sh off` restores immediately.

Original files and partitions are never written. A full power cycle clears every
runtime change; an enabled module applies again at a later soft reboot. An
independent guardian watches the session with cheap checks only (no periodic
`dumpsys`); failures disable the module and restore the stock library. Action
reports the verified runtime state and recovery steps.

## Build

```sh
python tools/build.py framebuffer10 --ndk /path/to/android-ndk
python modules/framebuffer10/tests/test_lifecycle.py
python modules/framebuffer10/tests/test_hooks.py
python modules/framebuffer10/tests/test_native_coordinated.py
python modules/mvhevc-eye-fix/tests/verify_package.py dist/framebuffer10/<zip> --contract-only
```

To regenerate the edit script after changing the recipe:

```sh
python modules/framebuffer10/payload-recipe/make_payload.py --stock stock.so \
  --tools /path/to/SPIRV-Tools/bin --emit-inc modules/framebuffer10/native/payload_patch.inc
```

Never commit or publish a generated library; see [NATIVE-NOTICE.txt](NATIVE-NOTICE.txt).

## Limits

- 10-bit SDR only.
- Separate draw calls blend in encoded space on the UNORM target, while the stock
  8-bit target blends in linear light. Soft edges of overlay layers (for example the
  gaze cursor) can look slightly darker.
- The vendor projection shaders apply the hand-mask and breakthrough highlights after
  their own encode; those highlights differ slightly from stock while active.
