# Galaxy XR Stream CPU Relief

Author: **4uva4ek**. Local unpublished 0.1.0, automatic package installed DISABLED.

Combines CLD's 17 October 2026 runtime findings: KXR LogLevel=0 in controller HAL private writable memory and nice -20 for Steam Link SCHED_OTHER threads named SVLRXThreadUDP, SVLMediaThread, NDK MediaCodec_, CodecLooper and Thread-9. Other scheduling policies, CPU affinity, system properties, Velocity Frame, Pose Time and Whitening are untouched. Thread-9 is the observed historical pipeline name; its semantic role is not guaranteed in future Steam Link versions. No claim of proven controller smoothness improvement.

Evidence: GalaxyXR/diagnostics/controller-tracking-survey-20261017/CLD-NOTES.md and GalaxyXR/diagnostics/steamlink-stream-live-20261017/runs/20261017-222633-ab-nice/. CLD observed HAL CPU 32–34% -> 16–22% of one core; selected thread queue wait fell 16–26%; same-bitrate miss rate fell about 18% in that experiment. Baselines and bitrate differed elsewhere. This module lifecycle has NOT been device-tested. User requested no new tests; only build/package/safety checks are performed.

Build from repository root: `python modules/stream-cpu-relief/build.py` (Linux NDK 29.0.14206865; ANDROID_NDK_HOME override). Output: `dist/stream-cpu-relief/gxr-stream-cpu-relief-0.1.0-auto.zip`. CI publishes from the same source with the shared builder (`python tools/build.py stream-cpu-relief --ndk PATH`) and NDK 28.2.13676358; the dedicated build.py remains the local NDK r29 device-test builder. The stable update feed is created and advanced by the release workflows.

Only `/proc/PID/mem` four-byte data write and per-thread setpriority are used. Exact original library SHA256, RX/private writable mappings, inode, original value 255, zero padding, relocated PrintlnCallbackDummy pointer, PID/start time are required. Already-zero LogLevel is an external experiment: refuse activation rather than take ownership. No ptrace, instruction patch, process suspension, original-file writes, mount, property, firmware, root startup changes or SELinux changes. HAL restart ends the worker and disables the module rather than retrying. Steam Link may restart normally; new matching threads are discovered every two seconds.

KernelSU disable/remove is the sole preference. Standard service startup waits for boot completion. A durable same-boot lease precedes modifications; per-target original priorities and identities are recorded in a root-only /dev journal before each mutation. Disable/removal restores owned values only; dead targets require no restore. Existing -20 threads are external and not owned. Health or activation errors disable and report the cause. A hard-killed helper can leave RAM changes until explicit `action.sh off` recovers the journal or a full power cycle; no watchdog or perfect rollback is claimed. PID/start checks narrow but do not eliminate the Linux numeric-TID setpriority race. The HAL memory FD binds writes to its original process. Any unresolved restoration keeps evidence and disables the module. Cold boot expires previous-boot lease/failure guards without changing ON/OFF; soft reboot preserves them.

Action is an English status/recovery report, never an activation toggle. Root recovery: `sh /data/adb/modules/gxr_stream_cpu_relief/action.sh off`. Keep OFF and fully power-cycle if restoration is unconfirmed. ON may reapply after startup, so reboot alone with ON is not rollback. Install with the reviewed KernelSU GXR installer; generic installer aborts. Do not enable or soft reboot without the user's separate request. Retain external experiments until their owner explicitly ends them. No publication authorization is implied.
