# Restart lifecycle update

- **Haptic MAIN 0.5.5:** after Android boot completes, wait up to 20 seconds for
  the controller service/JNI mapping; apply as soon as ready.
- **OpenXR Velocity Frame 0.3.3:** tolerate temporary Package Manager
  unavailability during announced restarts and recheck target identity.
- **Controller Whitening 0.1.3:** restore the previous owner before a planned
  restart, then reapply at the next service stage; improve pointer diagnostics.
- **Controller Extrapolation 0.4.2 / Timestamp Precision 0.1.2:** shared cold-boot
  guard reset and status updates; native patch behavior is unchanged.
- **All modules:** expire old interruption guards after a confirmed cold kernel
  boot without changing ON/OFF preferences. Same-boot failure guards remain.
- **Framebuffer10 0.3.1 (source-only):** use KernelSU's coordinated restart
  stages to prepare 10-bit SDR before Android starts, with per-phase logs.
  The proprietary compositor payload and local ZIP are not distributed.

Three consecutive soft restarts passed with Framebuffer10; the last two used
KernelSU GXR 1.0.3 and active Whitening. Haptics was verified active, Velocity
was waiting for an app, and no duplicate owners were found. Extrapolation and
Timestamp remained OFF. Local lifecycle/package tests passed.

The original Framebuffer `restart-started` exit 1 was not reproduced; its exact
cause remains unknown. Cold-boot validation of the final combination, visual
quality and native object throwing are not established by these tests.

Public packages are automatic-only and install disabled. Update disabled; enable
separately. [Protocol details and evidence](COORDINATED-RESTART-2026-10-11.md).
